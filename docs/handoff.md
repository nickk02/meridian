## Decisions made this session

- **Deploy pipeline is `wrangler deploy` run by hand, not automatic.** The README describes a Cloudflare Workers Builds pipeline triggered by pushing to `main`. That is not actually wired up: nothing was deployed between 2026-07-31 and 2026-08-11 despite multiple merges to `main` in between, confirmed via `wrangler deployments list`. Every deploy this session was a manual `wrangler deploy` I ran myself. The README's description is aspirational, not current behavior. This does not supersede an earlier decision; it's a fact that was never explicitly stated as a decision before.
- **Financial, cyber, and sports domains removed entirely**, not just hidden in the UI. They don't naturally geocode and had no plausible worldwide free data source. Supersedes the original 16-domain ontology described in early project docs; the ontology is 13 domains now.
- **GDELT is unusable from this environment and both sub-projects that depended on it are deferred, not built.** GEO 2.0 (`api/v2/geo/geo`) is dead outright, confirmed 404 on GDELT's own documented example URLs. DOC 2.0 (`api/v2/doc/doc`) worked once, then went into a 429 block that did not clear after 24+ hours of conservative retries. This supersedes the original plan to build a GDELT worldwide overlay and a GDELT-powered Inspector news panel; both are fully specced (`docs/superpowers/specs/2026-07-30-gdelt-worldwide-overlay-design.md`, `docs/superpowers/specs/2026-07-30-inspector-related-news-design.md`) but zero production code exists for either.
- **WHO Disease Outbreak News has a real structured API**, contrary to the original assumption that it was HTML-only. `who.int/api/news/diseaseoutbreaknews`, OData JSON, no key, confirmed live. This supersedes the earlier "WHO needs a feasibility spike" note; it does not, it was built this session.
- **Country matching in the WHO adapter must check longest names first.** A plain substring scan tagged a Papua New Guinea item as Guinea, because "Guinea" is a substring of "Papua New Guinea" and the table didn't even have Papua New Guinea in it yet. Fixed by sorting candidate country names longest-first and adding the three names most exposed to this pattern (Papua New Guinea, Equatorial Guinea, Guinea-Bissau). This was found by inspecting real production data after the first deploy, not by code review.
- **The Workers account is on the $5/mo paid plan**, not free tier. This happened for D1 write-headroom reasons unrelated to this session's feature work, but it changes the calculus for the still-unbuilt live-updating ticker: the README gates that feature behind "once sub-minute latency justifies leaving pure free-tier," and that's already happened for a different reason. The ticker plan (`docs/superpowers/plans/2026-08-08-live-ticker.md`) still uses the WebSocket Hibernation API to keep it cheap regardless.
- **Energy domain has no viable source.** Checked live: ODIN is US-county-only, GeoBlackout is crowdsourced (not official, fails this project's own sourcing bar), PowerOutage.us/com free tier is restricted to utility/emergency-management accounts. Stays deferred, same conclusion as before this session, just re-confirmed.

## Known broken / unverified

- **UNVERIFIED, possibly a real bug: the production navbar is rendering as if `isMobile` is true at desktop widths.** Checked live, twice, on two different browser tabs including a full fresh page load: at `window.innerWidth = 1280`, `window.matchMedia('(max-width: 820px)').matches` correctly returns `false`, but the navbar's right-hand group renders the mobile-branch content (view toggle only, no OBJECTS/LINKS/DOMAINS tags) instead of the desktop branch. `web/src/hooks.ts`'s `useIsMobile()` is called with no override (`web/src/App.tsx:27`), so the default 820px threshold should apply and this width should read as desktop. I could not tell whether this is a real production bug or an artifact of the specific automated browser tool used to check it (my own earlier testing this session did emulate a mobile viewport in the same browser tool, and I could not fully rule out state bleeding across tabs despite opening a genuinely new tab to test). Did not investigate further or touch any code, per this session's instructions. **Check this in a real browser before trusting it either way.**
- **NIFC reported `stale: true` on the last live ingest.** The adapter fell back to a previously-archived R2 blob instead of a fresh fetch. Not investigated; could be a transient upstream issue or something worth a closer look.
- **D1 write-budget headroom was not recalculated after adding the WHO feed.** The last real calculation is in project memory and is over 55 days old, predating WHO entirely. WHO isn't gated (runs every 15-minute cycle, unlike FIRMS/CAP/usgs_sig), and it's a new, unbounded-by-design write source. Worth a real check, not assumed safe.
- **Grounded summaries and the live-updating ticker are fully specced and planned but have zero code.** Do not assume any part of either exists. `worker/index.ts` has no `/api/summary` route, no `LiveTicker` class exists, `web/src/hooks.ts` has no `useSummary` or `useLiveTicker`.
- 6 Dependabot vulnerabilities (1 high, 5 moderate) are still open on the GitHub repo. Not looked at this session beyond noting they exist on every push.
